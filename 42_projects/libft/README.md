## 과제 개요

`libc`의 함수들을 `ft_` 접두사를 붙여 재구현합니다.  
빌드 결과물은 정적 라이브러리 `libft.a`로 아카이브되며, 이후 프로젝트에서 `-lft` 플래그로 링크합니다.

```bash
make        # libft.a 생성
make bonus  # 연결 리스트 함수 포함
```

```c
#include "libft.h"

// 이후 프로젝트 Makefile에서
cc main.c -L. -lft
```

허용 함수: `malloc`, `free`, `write`

## 왜 직접 구현하는가

표준 라이브러리 함수는 이미 검증되어 있고 최적화도 잘 되어 있습니다.  
그럼에도 직접 구현하는 이유는 다음과 같습니다.

**내부 동작을 이해하기 위해**  
`ft_strlen`이 `\0`을 만날 때까지 포인터를 이동한다는 사실, `ft_memcpy`가 겹치는 메모리 영역을 처리하지 못한다는 사실, `ft_memmove`가 이를 방향을 조정해 처리한다는 사실 등 함수의 정확한 동작 방식을 파악하게 됩니다.

**엣지 케이스를 직접 처리하며 방어적 코딩을 익히기 위해**  
`NULL` 포인터, 길이 0, 빈 문자열, 정수 경계값 등 표준 함수가 어떻게 처리하는지 직접 구현하며 배웁니다.

**이후 프로젝트에서 수정·확장하기 위해**  
직접 만든 라이브러리는 필요에 따라 자유롭게 수정할 수 있습니다.  
get_next_line, ft_printf 등 이후 과제에서 libft를 링크해 재사용했습니다.

## 핵심 구현 포인트

### ft_memcpy vs ft_memmove

두 함수 모두 메모리를 복사하지만 겹치는 영역 처리가 다릅니다.

```
src:  [1][2][3][4][5]
dst:        [3][4][5][6][7]  ← src와 일부 겹침
```

`ft_memcpy`는 앞에서부터 복사하므로 겹치는 경우 src 데이터를 덮어쓰기 전에 읽어야 할 값이 손상될 수 있습니다.  
`ft_memmove`는 src와 dst의 위치를 비교해 겹치는 경우 뒤에서부터 복사해 이 문제를 방지합니다.

```c
// ft_memmove 핵심 로직
if (dst > src && dst < src + n)
    // 뒤에서부터 복사 (역방향)
else
    // 앞에서부터 복사 (정방향)
```

### ft_strlcpy vs ft_strncpy

`strncpy`는 목적지 버퍼에 `\0`을 보장하지 않고, 짧은 문자열을 복사할 때 나머지를 `\0`으로 패딩합니다.  
`strlcpy`는 항상 `\0`을 보장하며, 반환값으로 원본 문자열 길이를 돌려줘 잘림 여부를 확인할 수 있습니다.

```c
// 잘림 감지
if (ft_strlcpy(dst, src, size) >= size)
    // 잘렸음
```

### ft_atoi

단순 숫자 변환을 넘어 여러 엣지 케이스를 처리해야 합니다.

- 앞 공백 (`' '`, `'\t'`, `'\n'`, `'\r'`, `'\f'`, `'\v'`) 건너뛰기
- 부호 (`+`, `-`) 처리
- 숫자가 아닌 문자 등장 시 중단
- `INT_MAX`, `INT_MIN` 범위 처리

### ft_itoa

`INT_MIN` (`-2147483648`) 처리가 까다롭습니다.  
절댓값을 취하면 `int` 범위를 벗어나므로 `unsigned int`로 캐스팅하거나 별도 예외 처리합니다.  
자릿수 계산 → `malloc` → 역순 채우기 순서로 구현합니다.

### ft_split

반환 타입이 `char **` (2차원 배열)이고 `malloc`을 여러 번 호출합니다.  
중간에 `malloc` 실패 시 이미 할당된 메모리를 전부 해제해야 합니다.  
할당 실패를 대비한 `free_all` 헬퍼 함수를 먼저 작성하는 것이 좋습니다.

## 보너스: 연결 리스트

단일 연결 리스트 조작 함수를 구현합니다.

```c
typedef struct s_list {
    void            *content;
    struct s_list   *next;
} t_list;
```

| 함수 | 설명 |
|---|---|
| `ft_lstnew` | 새 노드 생성 |
| `ft_lstadd_front` | 리스트 앞에 노드 추가 |
| `ft_lstadd_back` | 리스트 끝에 노드 추가 |
| `ft_lstsize` | 리스트 노드 수 반환 |
| `ft_lstlast` | 마지막 노드 반환 |
| `ft_lstdelone` | 노드 하나 삭제 (content 해제 함수 인자로 전달) |
| `ft_lstclear` | 리스트 전체 삭제 |
| `ft_lstiter` | 각 노드에 함수 적용 |
| `ft_lstmap` | 각 노드에 함수 적용해 새 리스트 반환 |

`content`를 `void *`로 선언한 이유는 어떤 타입의 데이터도 저장할 수 있는 범용 리스트를 만들기 위해서입니다.  
삭제 함수(`ft_lstdelone`, `ft_lstclear`)가 `del` 함수 포인터를 인자로 받는 이유도 마찬가지로, content 타입에 맞는 해제 방법을 외부에서 주입받기 위해서입니다.

## 깨달은 점

**표준 함수의 명세를 정확히 읽어야 한다**  
`man` 페이지를 처음부터 끝까지 꼼꼼히 읽지 않으면 엣지 케이스를 놓칩니다.  
반환값, `NULL` 처리, 겹치는 메모리 처리 여부 등 세부 명세가 중요합니다.

**메모리 누수는 반드시 막아야 한다**  
`ft_split`처럼 여러 번 `malloc`하는 함수에서 중간 실패 시 이전에 할당된 메모리를 전부 해제해야 합니다.  
정상 경로뿐만 아니라 에러 경로에서도 항상 메모리를 정리하는 습관이 중요합니다.

**포인터 산술을 자유롭게 다뤄야 한다**  
`memcpy`, `memmove` 등 메모리 함수는 포인터 연산이 핵심입니다.  
`char *`로 캐스팅해 바이트 단위로 접근하는 방법을 완전히 이해해야 합니다.

**재사용 가능한 라이브러리 설계**  
이후 프로젝트에서 libft를 링크해 쓰면서 "잘 만든 라이브러리 하나가 얼마나 편한지"를 몸소 경험했습니다.  
처음에 꼼꼼하게 구현해둔 덕에 이후 프로젝트에서 기본적인 문자열/메모리 처리를 빠르게 진행할 수 있었습니다.
