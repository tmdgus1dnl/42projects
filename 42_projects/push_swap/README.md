# push_swap

> 42Seoul | C | 점수: 125/100 | 소요 기간: 3주 | 재시도: 2회

두 개의 스택(`a`, `b`)과 제한된 연산만으로 정수 배열을 **최소 연산 횟수로 정렬**하는 알고리즘 프로젝트입니다.  
표준 알고리즘을 그대로 쓰지 않고 **gap 기반 우선순위 판단**을 직접 고안해 구현했습니다.  
평가자들로부터 뛰어난 프로젝트 피드백을 받았습니다.

## 과제 개요

`stack a`에 정수들이 들어옵니다. `stack b`는 처음에 비어있습니다.  
아래 11가지 연산만 사용해 `stack a`를 오름차순으로 정렬해야 합니다.

| 연산 | 설명 |
|---|---|
| `sa` / `sb` / `ss` | 스택 top 2개 스왑 / 동시 수행 |
| `pa` / `pb` | b→a / a→b top 1개 push |
| `ra` / `rb` / `rr` | 스택 위로 회전 (top→bottom) / 동시 수행 |
| `rra` / `rrb` / `rrr` | 스택 아래로 회전 (bottom→top) / 동시 수행 |

`pa`와 `pb`를 연속으로 수행하면 원래 상태로 돌아오므로 의미가 없습니다.

## 스택 구현 방식

스택을 연결 리스트로 구현했습니다.

```c
typedef struct s_stack {
    int             val;
    int             gap;      // 우선순위 계산용
    struct s_stack  *prev;
    struct s_stack  *next;
} t_stack;
```

**stack의 top을 리스트의 마지막 노드로 설정했습니다.**  
`push`, `pop` 등 스택 주요 연산이 top에서 이루어지는데, 연결 리스트에서 마지막 노드의 추가/삭제가 구조상 편리하기 때문입니다.

**입력 순서**  
첫 번째 매개변수가 `stack a`의 top에 위치해야 합니다. 즉 마지막 노드에 해당합니다.  
파싱 시 입력 순서를 반대로 삽입해야 합니다.

## 정렬 알고리즘 설계 과정

처음부터 나만의 알고리즘을 고안하기 위해 다양한 아이디어를 시도했습니다.

**초기 아이디어 — 점수 기반 명령어 선택**  
명령어 하나를 수행했을 때 `stack a`가 오름차순, `stack b`가 내림차순에 가까울수록 높은 점수를 부여해 최적 명령어를 선택하는 방식을 구상했습니다.  
하지만 모든 명령어를 매번 평가하는 비용이 너무 컸습니다.

**gap 기반 우선순위로 전환**  
`stack b`의 각 원소에 `gap` 값을 부여했습니다.  
`gap`은 해당 원소가 `stack a`의 top 원소와 얼마나 가까운지를 나타냅니다.  
`gap`이 작을수록 `push_a` 시 올바른 위치에 삽입될 가능성이 높습니다.

노드 멤버 변수에 `gap`을 추가하고, `stack b`의 모든 원소와 `stack a` top을 비교해 차이값을 기록했습니다.

**weight 계산으로 정교화**  
`gap`만으로는 최적이 아닌 경우가 있었습니다.  
`b`의 top까지의 인덱스 거리도 함께 계산해 `weight = gap + index 거리`로 합산하고, weight가 가장 작은 원소를 우선 처리하는 방식으로 발전시켰습니다.

## 최종 알고리즘

### 소규모 입력 (5개 이하)

5개 이하는 경우의 수가 적어 최적 시퀀스를 직접 하드코딩했습니다.  
2~3개는 최적 고정 시퀀스, 4~5개는 재귀적으로 분해해 처리합니다.

### 대규모 입력

**1단계: a → b push (sort_a)**  
3개가 남을 때까지 `stack a`에서 `stack b`로 push합니다.  
이때 `stack b`가 내림차순을 유지하도록 하며, push 전 `stack a` 내부 정렬 조건을 먼저 확인합니다.

```
sort_a 반복문 1: stack a의 bottom이 top보다 작고, b의 top보다 크면 먼저 a 내부 정렬
sort_a 반복문 2: b의 top보다 크고, gap이 가장 작은 수를 a의 top으로 올린 뒤 push_b
```

**2단계: b → a push (sort_b)**  
`stack b`에서 `stack a`로 원소를 하나씩 가져옵니다.  
매번 `weight`(gap + 인덱스 거리)가 가장 작은 원소를 선택해 `stack a`의 올바른 위치에 삽입합니다.

```
1. b의 모든 원소의 weight 계산
2. 가장 weight이 작은 원소를 rb / rrb로 top으로 이동
3. push_a: b의 top < a의 top이면 push, 크면 ra / rra로 a를 먼저 회전
4. 반복
```

**3단계: 마무리 정렬**  
`stack b`가 비면 `stack a`에서 최솟값이 top이 되도록 `ra` 또는 `rra`로 회전합니다.

## 명령어 최적화

**`rr` / `rrr` 활용**  
`ra`와 `rb`가 같은 방향으로 동시에 필요한 경우 `rr` 한 번으로 대체합니다.  
`rra`와 `rrb`도 마찬가지로 `rrr`로 통합합니다.  
두 방향이 다를 경우에는 개별 연산을 사용합니다.

**불필요한 push 제거**  
`pa`와 `pb`를 연속으로 수행하면 원래 상태로 돌아오므로 실질적으로 연산을 소비하기만 합니다.  
push 조건 판단 시 이를 방지하는 조건을 추가했습니다.

## 보너스: checker

`push_swap`이 출력한 연산 시퀀스를 입력받아 실제로 수행하고 결과가 올바른지 검증합니다.

```bash
ARG="3 2 1"
./push_swap $ARG | ./checker $ARG
# → OK
```

`get_next_line`으로 연산 명령을 한 줄씩 읽어 순서대로 실행하고, 최종 `stack a`가 오름차순이고 `stack b`가 비어있으면 `OK`, 아니면 `KO`를 출력합니다.

## 깨달은 점

**그리디 알고리즘은 설계가 핵심이다**  
매 단계에서 최선을 선택하는 그리디 방식은 구현이 간단해 보이지만, 어떤 기준으로 "최선"을 정의하느냐가 결과를 완전히 바꿉니다.  
gap과 인덱스 거리를 합산한 weight가 효과적인 기준이 됐지만, 이 결론에 도달하기까지 여러 번의 시도와 폐기가 필요했습니다.

**자료구조 설계가 구현 편의성을 결정한다**  
stack의 top을 리스트의 마지막 노드로 정하는 것 하나로 push, pop, swap 연산 구현이 훨씬 단순해졌습니다.  
자료구조를 어떻게 설계하느냐가 그 위에 쌓이는 알고리즘 구현 전체에 영향을 줍니다.

**직접 알고리즘을 고안하는 것이 값지다**  
표준 Turk 알고리즘이나 다른 사람의 방식을 그대로 쓰지 않고 gap 기반 우선순위를 스스로 고안한 경험이 인상 깊었습니다.  
결과적으로 평가자들에게도 좋은 반응을 받았고, 알고리즘과 자료구조가 나와 잘 맞는다는 걸 확인했습니다.
