# get_next_line

> 42Seoul | C | 점수: 125/100 | 재시도: 1회

파일 디스크립터에서 한 줄씩 읽어오는 함수 `get_next_line()`을 구현한 프로젝트입니다.  
Mandatory는 단일 fd, Bonus는 **여러 fd를 동시에 관리**하며 각 파일의 읽기 위치를 독립적으로 기억합니다.

## 과제 개요

```c
char *get_next_line(int fd);
```

호출마다 `fd`에서 다음 줄(`\n` 포함)을 반환합니다. EOF 또는 오류 시 `NULL` 반환.  
`BUFFER_SIZE`는 컴파일 타임에 `-D BUFFER_SIZE=n`으로 자유롭게 설정할 수 있습니다.

**Bonus 요구사항**  
여러 fd에 번갈아 `get_next_line()`을 호출해도, 각 fd의 읽기 위치를 독립적으로 기억해야 합니다.

## 핵심 개념

### static 변수

함수가 종료되어도 값이 사라지지 않는 변수입니다.  
`get_next_line()`은 호출마다 독립적으로 실행되지만, 이전 호출에서 읽다 남은 데이터를 다음 호출까지 기억해야 합니다.  
이를 가능하게 하는 것이 `static` 변수입니다.

```c
static char buff[BUFFER_SIZE + 1];
```

`static` 변수는 선언 시 자동으로 0으로 초기화됩니다.  
명시적으로 `= 0`으로 재초기화하면 주소를 기억하기 위해 `static`으로 선언한 의미가 없어집니다.

### BUFFER_SIZE와 read()

`read(fd, buf, BUFFER_SIZE)`는 최대 `BUFFER_SIZE` 바이트를 읽어 `buf`에 저장하고 실제로 읽은 바이트 수를 반환합니다.  
`BUFFER_SIZE`가 작으면 `read()` 호출이 많아지고, 크면 한 번에 많이 읽어 `\n` 이후의 데이터가 버퍼에 남습니다.  
남은 데이터를 다음 호출 때 재사용해야 하므로 버퍼 관리가 핵심입니다.

## Mandatory 구현

### 전체 흐름

```
get_next_line(fd)
    │
    ├── static buff에 잔류 데이터가 있는가?
    │       있으면 → 잔류 데이터를 ret_str 앞에 붙임
    │
    ├── \n이 나올 때까지 read() 반복
    │       읽은 데이터를 ret_str에 누적
    │
    ├── \n 발견 시
    │       ret_str = \n 이전까지 + \n
    │       buff = \n 이후 남은 데이터 (다음 호출에서 재사용)
    │
    └── ret_str 반환
```

### 버퍼 관리 (get_buff)

`static buff` 안에 `\n` 이후에 남은 문자열을 기억합니다.  
다음 호출 시 `read()` 전에 `buff`의 잔류 데이터를 먼저 확인해 `ret_str` 앞에 삽입합니다.

```
[이전 호출 버퍼 상태]
"hello\nworld\n"
       ↑ 여기까지 반환, "world\n"은 buff에 보존

[다음 호출]
buff에서 "world\n" 발견 → read() 없이 반환
```

### 문자열 재할당 (realloc)

C에는 문자열을 동적으로 늘려주는 함수가 없기 때문에 직접 구현했습니다.  
기존 문자열을 새 메모리에 복사하고 뒤에 새 버퍼를 붙인 뒤 새 포인터를 반환합니다.

## Bonus 구현: 다중 fd 지원

여러 fd에서 번갈아 호출해도 각 fd의 읽기 상태를 독립적으로 유지해야 합니다.

### 이중 연결 리스트 구조

fd마다 노드를 생성해 리스트로 관리합니다.

```c
typedef struct s_gnl_list {
    char    *ret_str;    // 반환할 문자열 (개행 이전)
    char    *next_str;   // 다음 노드에 넘길 잔류 문자열 (개행 이후)
    int     node_fd;     // 이 노드가 담당하는 fd
    struct s_gnl_list *prev;
    struct s_gnl_list *next;
} t_gnl_list;
```

### 리스트 반복 로직

```
1. prev 포인터로 리스트를 역순 탐색
2. node_fd == fd인 노드 발견 시 반복 시작

3. 현재 노드의 next_str에 \n이 있는가?
   있으면 → read() 없이 개행 전까지 다음 노드의 ret_str로 이동
            개행 이후는 다음 노드의 next_str에 저장
   없으면 → 현재 노드의 next_str을 다음 노드의 ret_str 앞에 붙이고
            \n이 나올 때까지 read() 수행, 다음 노드의 ret_str에 누적

4. 작업 완료 후 현재 노드의 next_str은 free (메모리 누수 방지)
```

## 주요 함수 설명

| 함수 | 역할 |
|---|---|
| `get_next_line(fd)` | 진입점. fd에서 다음 줄을 반환 |
| `get_buff()` | static buff 관리. 잔류 데이터 보존 및 재사용 |
| `realloc()` | 문자열 동적 확장. 기존 str + 새 buff → new_str 반환 |
| `make_node()` | 새 노드 생성 및 초기화 |
| `find_node()` | 리스트에서 해당 fd 노드 탐색 (역순) |
| `free_node()` | 노드 및 내부 문자열 해제 |

## 디버깅 기록

**빈 문자열이 NULL 대신 반환**  
`substr()`에서 길이가 0일 때도 빈 문자열을 할당해 반환했습니다.  
길이가 0이면 할당 전에 바로 `NULL`을 반환하도록 수정했습니다.

**fd 안에 NULL이 있을 때 메모리 누수**  
파일 내용에 `NULL`이 포함된 경우 `ret_str`이 빈 상태에서 노드와 내부 문자열이 해제되지 않아 누수가 발생했습니다.  
`ret_str`이 없을 때 노드와 하위 문자열까지 전부 해제하도록 처리했습니다.

**malloc 실패 시 리스트 일부만 해제**  
`malloc`이 실패해 `NULL`을 반환했을 때 바로 리턴하면, 같은 fd를 가진 나머지 노드들이 해제되지 않은 채 남았습니다.  
`malloc` 실패 시 해당 노드까지의 같은 fd 노드들을 전부 해제한 뒤 리턴하도록 수정했습니다.

**strict 옵션에서 malloc protection 에러**  
노드 몇 개와 내부 문자열들이 제대로 해제되지 않는 문제였습니다.  
`new`가 `NULL`일 때 바로 리턴하면 남은 리스트들이 해제되지 않는다는 점을 발견하고, 해제 로직을 추가해 해결했습니다.

## 깨달은 점

**static 변수는 목적에 맞게 써야 한다**  
상태를 기억하기 위해 `static`을 쓰는 것인데, 함수 내부에서 `= 0`으로 재초기화하면 기억해야 할 주소가 사라집니다.  
`static` 변수는 선언 시 자동 초기화되므로 명시적 초기화가 필요한 경우를 신중하게 판단해야 합니다.

**이중 포인터와 주소 처리를 명확히 해야 한다**  
리스트 함수를 작성할 때 이중 포인터로 리스트 주소를 받아야 하는 경우와 단순 포인터로 처리하는 경우를 구분하는 것이 중요합니다.  
처음 들어온 주소를 보존해야 정상적으로 반환되는 경우와 그렇지 않은 경우가 있어 혼동하기 쉽습니다.

**에러 경로에서도 메모리를 전부 해제해야 한다**  
정상 경로만 메모리 해제를 고려하고 에러 경로를 놓치면 누수가 발생합니다.  
`malloc` 실패, `NULL` 반환, 예외 케이스마다 해제 로직을 별도로 처리해야 합니다.

**버퍼 크기에 무관하게 동작해야 한다**  
`BUFFER_SIZE=1`이든 `BUFFER_SIZE=10000`이든 정확히 동작해야 합니다.  
극단적인 버퍼 크기로 테스트하면 잠재적인 버그를 더 쉽게 발견할 수 있습니다.
